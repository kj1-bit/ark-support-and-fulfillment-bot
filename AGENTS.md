# Repository Instructions

- Work only on the current feature branch. Never modify main directly.
- Never merge, deploy, push, force-push, or open a pull request without explicit approval.
- Never access or modify production deployment files, secrets, .env files, runtime databases, or private configuration.
- Before editing, inspect the relevant files and explain the planned change.
- Keep changes narrowly scoped.
- Run focused tests first, then broader tests when appropriate.
- Before stopping, report changed files, tests run, failures, security or compatibility concerns, rollback guidance, and the exact next step.
- Preserve V1 behavior and do not activate or replace production with V2.
- Treat docs/V2_ROADMAP.md as the continuity record for V2 work.
